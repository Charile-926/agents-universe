# 数据分析看板 · 项目前提信息包

> 模拟项目：云栖优选经营分析看板。本文中的指标、数据量、差异值为演练用模拟数据。

## 1. 项目背景

云栖优选在 2024 年之前用「各业务线各自取数 + Excel 周报」的方式看经营数据：订单、支付、退款、商品、用户分散在 6 个库，同一个「GMV」在财务、运营、商品三个团队能算出三个数。2025 年上线统一数据看板，服务集团 32 家线下门店和线上商城，覆盖高管、运营、商品、门店四类用户。

看板当前日均访问 1,900 人次，核心指标 5 个（GMV、订单量、客单价、支付转化率、复购率），支持按日/周/月、渠道/品类/地区/新老客筛选。数据 T+1 更新，每日 02:00 跑批，平均 38 分钟完成。

本项目 2027 年的重点是：**统一指标口径、缩短数据就绪时间、把「看板数字和明细对不上」的客诉降下来**。

## 3. 范围与边界

**范围内**：指标定义与版本、数据源接入、ETL 调度、汇总层模型、看板查询 API、前端图表与筛选、数据质量校验、口径说明。

**范围外**：业务系统的在线交易（只读）、财务总账、用户画像标签生产、A/B 实验平台。

**数据源**：

| 支付库 | payments, refunds | 增量 binlog | 支付团队 |

## 4. 指标口径（v2026.11）

| 指标 | 口径 | 注意点 |
| --- | --- | --- |
| GMV | 已支付订单金额之和，含运费，不含退款 | 退款在退款发生日冲减，不回溯原订单日 |
| 订单量 | 支付成功订单数，按 order_id 去重 | 拆单按子订单计 1 |
| 客单价 | GMV / 订单量 | 订单量为 0 显示「-」 |
| 支付转化率 | 支付订单数 / 下单数 | 分母为 0 显示「-」 |
| 复购率 | 周期内下单 ≥ 2 次用户 / 下单用户 | 按 user_id 去重，跨渠道合并 |
| 退款率 | 退款金额 / GMV | 按退款发生日 |
| 门店坪效 | 门店 GMV / 营业面积 | 仅线下门店 |

**时间口径**：自然日按 UTC+8，00:00:00–23:59:59；周从周一开始；月按自然月；同比对比去年同口径日期。

**维度**：渠道（自然流量/投放/活动/门店）、品类（一级/二级）、地区（大区/城市）、新老客（首单 90 天内为新客）。

## 5. 数据链路与模型

### 5.1 分层

- ODS：binlog/文件原样入湖，保留 90 天。
- DWD：订单、支付、退款、用户、商品明细宽表，按日分区。
- DWS：`dws_business_daily`（日期 × 渠道 × 品类 × 地区），预聚合 GMV、订单量、下单数、支付数、退款额、用户数。
- ADS：看板查询表，按指标 + 维度组合建 6 张结果表。

### 5.2 调度

1. 02:00 抽取昨日增量（binlog + 文件）。
2. 02:05 清洗、去重、维度补全。
3. 02:20 写入 DWS，跑质量校验。
4. 02:30 刷新 ADS 与缓存。
5. 02:35 发送「数据已就绪」通知；失败则告警并保留昨日快照。

### 5.3 容量

| 数据项 | 规模 |
| --- | --- |
| dwd_order | 2.1 亿行，日增 1.8 万 |
| dwd_payment | 2.3 亿行，日增 2.1 万 |
| dws_business_daily | 146 万行（4 年 × 维度组合） |
| ADS 结果表 | 6 张，单表 < 500 万行 |
| 看板查询 QPS | 峰值 120 |
| 单次查询扫描 | < 200 万行 |

## 7. 数据质量规则

| 规则 | 阈值 | 失败动作 |
| --- | --- | --- |
| 订单量 = 支付成功明细去重数 | 完全相等 | 阻断发布，告警 |
| GMV 与支付流水差额 | ≤ 0.01 元 | 告警，人工核对 |
| 主键唯一 | 0 重复 | 阻断 |
| 缺失日期 | 补 0 | 记录 |
| 维度空值率 | < 0.5% | 告警 |
| 同比波动 | > 30% 需说明 | 告警 |

## 8. 角色与权限

| 角色 | 数据范围 | 能力 |
| --- | --- | --- |
| 高管 | 全集团 | 看所有指标 |
| 运营 | 所辖渠道/品类 | 看板、导出（≤ 5 万行） |
| 商品 | 所辖品类 | 品类分析 |

行级权限由 `data_scope` 控制；导出需审批；手机号等明细字段默认脱敏。

## 9. 已知问题与风险

| 问题 | 证据 | 影响 |
| --- | --- | --- |
| GMV 含退款口径不一致 | 财务口径 3.21 亿 vs 看板 3.28 亿 | 管理层质疑 |
| 时区错位 | 门店 POS 用本地时间，线上用 UTC | 跨日订单归错日期 |
| 缺失日期填前值 | 某次故障用了前一天数据 | 虚增 GMV |
| 除零 | 新品类无订单时客单价 NaN | 前端空白 |
| 大促当天 T+1 延迟 | 双 11 次日 04:10 才就绪 | 早会拿不到数 |

## 10. 验收与演练关注点

1. 同一筛选条件下，看板 GMV 与明细 SQL 差额 ≤ 0.01 元。
2. 订单量为 0 时，客单价显示「-」而不是 NaN/Infinity。
3. 缺失日期补 0，不能用前一天数据填充。
4. 口径变更后，历史看板要能按版本回放。
5. 数据未就绪时，看板显示「数据更新中」和上次成功时间，不展示半成品。

## 11. 给智能体的前提假设

- 指标口径以本文件 v2026.11 为准；发现冲突时先停下来确认，不要自行发明口径。
- 任何指标变更必须同时更新「口径说明 + 版本号 + 影响看板清单」。
- 明细数据涉及用户隐私，默认脱敏，不在对话中输出完整手机号。
