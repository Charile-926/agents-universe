## 2. 被删掉的草稿内容

| 草稿内容 | 处理 | 原因 |
| --- | --- | --- |
| `slug: distilled-30108b-...` | 改为 `domain/ecommerce-oversell-incident-response` | 时间戳 slug 无法复用，也不能被触发词稳定命中 |
| 触发词只有 1 条会话标题 | 扩为 6 条业务短语 | 平台提示触发词要覆盖不同说法；实际用户不会原样复述标题 |
| 「先执行 sql_query，再执行 filesystem」这类通用句式 | 改为 S2/S3 的具体查什么、看到什么算什么 | 草稿只统计工具转移，没有领域语义 |
| 「历史上 sql_query 失败 1 次」 | 改为「查 inventory_segment 前先确认表存在」 | 失败原因是表未建，不是工具问题 |
| 「产出参考」5 条对话摘要 | 删除 | 摘要对执行没有指导价值，改为复盘模板与检查清单 |
| 通用质量清单 4 条 | 扩为 8 条领域检查项 | 原清单太泛，无法验收超卖修复 |

## 4. 一句话总结

草稿回答的是「这次对话用了什么工具」；精炼后的 Skill 回答的是「下次遇到同样故障，第一步查什么、看到什么算什么、怎么修、怎么验、怎么回滚」。前者是记录，后者才是可复用的工作方法。
