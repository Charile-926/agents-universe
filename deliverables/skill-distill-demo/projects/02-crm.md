# CRM 客户管理系统 · 项目前提信息包

> 模拟项目：云帆科技 SaaS 销售 CRM。本文中的公司、指标、数据均为演练用模拟数据。

## 1. 项目背景

云帆科技是一家做企业数字化工作台的 SaaS 公司，销售团队 120 人，分为 6 个大区。2023 年之前销售用 Excel + 企业微信管理客户，线索重复率超过 15%，跟进过程不可见，管理层拿不到可信的漏斗数据。

2024 年上线自研 CRM，覆盖「线索 → 客户 → 联系人 → 商机 → 合同 → 回款」全流程。当前年新增线索 8.6 万条、客户 2.3 万家、商机 1.1 万个，整体赢单率 23%，平均客单价 6.8 万元，平均销售周期 67 天。系统同时对接企业微信（消息与客户联系）、呼叫中心（通话记录）、电子签（合同签署）。

本项目 2027 年的重点是：**把线索分配、跟进时效、商机阶段和权限审计做扎实**，让主管看到真实漏斗，让销售少填表。

## 3. 范围与边界

**范围内**：线索池、线索分配与回收、客户/联系人、商机与阶段、跟进记录与提醒、合同与回款记录、销售漏斗与业绩看板、导出与审计。

**范围外**：呼叫中心话务能力（只接收通话记录）、电子签法律效力（第三方）、财务总账、市场投放平台。

**外部集成**：

| 系统 | 方向 | 数据 | 失败处理 |
| --- | --- | --- | --- |
| 企业微信 | 双向 | 客户联系、群消息、审批 | 消息失败重试 3 次，落站内信 |
| 呼叫中心 | 入 | 通话记录、录音 URL | 每小时补偿拉取 |
| 电子签 | 出/入 | 合同签署状态 | 签署回调重试 24h |

| 数据仓库 | 出 | 线索/商机/合同宽表 | T+1，失败重跑 |

## 5. 核心流程与规则

### 5.1 线索生命周期

`NEW → ASSIGNED → FOLLOWING → CONVERTED`；异常分支 `INVALID`（无效）、`RECYCLED`（回收回公海）。

- 线索来源：官网、活动、投放、转介绍、展会、手工录入。
- 分配规则：按大区 + 行业 + 销售负载轮询；主管可手动改派。
- 回收规则：分配后 48 小时未跟进自动回收；连续 2 次回收进入公海池。
- 转化：线索转客户时保留 `converted_from_lead_id`，并补全公司、行业、联系人。

### 5.2 商机阶段

`初步接触 → 需求确认 → 方案报价 → 商务谈判 → 赢单/输单`。

- 阶段只能向前推进；回退必须填写原因，并记录操作人。
- 赢单必须关联合同金额与签约日期；输单必须选择输单原因（价格/竞品/需求不符/预算/其他）。
- 超过 7 天未跟进标记「待跟进」，超过 14 天进入主管预警列表。
- 商机金额变更超过 20% 需要主管审批。

### 5.3 权限模型

- 行级权限：销售只能看 `owner_id = 自己` 的客户/商机；主管看团队；运营/管理员看全量。
- 字段级权限：成本、折扣底线、回款账号仅主管可见。
- 导出：必须二次确认，记录导出人、条数、字段、IP、时间；单次上限 5 万行。
- 跨区转移客户：需要原主管和目标主管双方确认。

## 8. 非功能与合规

- 客户手机号、邮箱在列表页脱敏（138****5678）；详情页查看完整值需要记录查看日志。
- 所有导出、批量修改、权限变更必须写审计日志，保留 3 年。
- 线索分配接口 P99 < 200ms；漏斗查询 P99 < 800ms（预聚合）。
- 每日 02:00 跑线索去重任务，输出重复组报告。
- GDPR/个人信息保护：注销客户后 30 天内完成匿名化。

## 9. 已知问题与风险

| 问题 | 证据 | 影响 |
| --- | --- | --- |
| 手机号格式不统一 | 历史数据含空格、+86、全角 | 去重漏判 |
| 商机阶段被跳级 | 日志显示 12% 从「初步接触」直接到「方案报价」 | 漏斗失真 |
| 导出绕过前端限制 | 有销售用 API 直接导出 8 万行 | 数据泄露风险 |
| 主管跨区查看 | 权限 SQL 漏了 region 条件 | 越权 |
| 跟进提醒时区 | 服务器 UTC，销售看北京时间 | 提醒延迟 8 小时 |

## 10. 验收与演练关注点

1. 同一手机号不同格式（含 +86、空格）录入，必须命中同一条线索。
2. 销售尝试访问他人客户，返回 404 而非 403。
3. 商机阶段回退未填原因，接口返回 400。
4. 导出超过 5 万行被拒绝，且审计日志有记录。
5. 7 天未跟进商机在主管看板出现，且时区正确。

## 11. 给智能体的前提假设

- 本文件中的客户、金额、人员均为模拟数据。
- 涉及权限的改动，必须同时给出「销售 / 主管 / 运营 / 管理员」四种角色的验证用例。
- 涉及客户数据的导出、日志、脱敏，默认按最严格口径处理。
